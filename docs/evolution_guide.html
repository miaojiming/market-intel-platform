数据飞轮 — 持续进化指南

让系统在使用过程中自动收集数据、发现问题、优化 Prompt、验证改进

核心理念

数据飞轮是一个自我强化的闭环：系统每次运行都会产生新数据，这些数据反哺评测集，评测集检测出薄弱环节，驱动 Prompt 和模型优化，优化后的系统又能采集更好的数据——越用越好，持续进化。

四步闭环详解

1

采集 — 持续扩充评测集

每次发现新的真实文章（不管是系统采集的还是人工发现的），都加入评测集。评测集越大，评测越可靠。

2

评测 — 跑 AI Evals

用当前的 Prompt 和模型对评测集跑一轮完整评测，计算格式合规、真实性、综合质量三个指标。

3

对比 — 基线检测

将当前得分与基线对比。如果分数下降超过 0.05，触发回归告警；如果分数提升超过 0.01，自动更新基线。

4

优化 — 改 Prompt / 换模型

根据评测发现的薄弱点（哪条用例得分低、哪个指标差），针对性优化 Prompt 或尝试新模型，然后回到第 2 步验证。

工具与命令

1. 运行进化流水线

一键执行：评测 → 对比基线 → 输出报告 → 自动更新基线

cd 项目目录
python scripts/eval_pipeline.py

退出码 0 = 无回归（可用于 CI 门禁），退出码 1 = 检测到回归。

2. 添加新用例到评测集

发现新的真实文章时，加入评测集：

python scripts/add_golden.py \
  --id case-011 \
  --input "文章全文内容" \
  --source "来源名称" \
  --url "https://真实链接" \
  --expected "预期摘要（可选）" \
  --importance 5

3. 查看历史进化轨迹

每次运行的结果都保存在 eval/.evals/history/ 目录，可以追踪质量变化轨迹：

ls eval/.evals/history/
# run_20260831_120000.json
# run_20260901_080000.json
# ...

4. 对比两次运行

对比任意两次运行的结果，看哪些用例进步了、哪些退步了：

python -c "
import json
r1 = json.load(open('eval/.evals/history/run_20260831_120000.json'))
r2 = json.load(open('eval/.evals/history/run_20260901_080000.json'))
for m in ['schema_validation','faithfulness','geval','overall_weighted']:
    o, n = r1['metrics'][m], r2['metrics'][m]
    d = n - o
    print(f'{m}: {o:.2f} → {n:.2f} ({\"↑\" if d>0 else \"↓\" if d<0 else \"→\"}{abs(d):.2f})')
"

典型进化场景

场景触发方式预期效果
Prompt 优化 修改 prompts/summarize.txt → 跑 eval_pipeline.py 发现真实性从 0.90 → 0.95，自动更新基线
模型升级 换更强模型 → 跑 eval_pipeline.py → 对比基线 综合质量从 0.95 → 0.98，数据驱动选型
回归检测 Prompt 改动后跑评测，发现某个指标下降 退出码 1，CI 阻止合并，避免质量下降
数据扩充 用 add_golden.py 加入新真实文章 评测集从 10 条 → 20 条，覆盖面更广

CI/CD 集成（AI-DLC Operations）

将 eval_pipeline.py 集成到 CI/CD 流水线，实现 评测门禁——每次代码或 Prompt 变更必须通过评测才能合并。

GitHub Actions 示例：

name: AI Eval Gate
on:
  pull_request:
    paths:
      - 'eval/prompts/**'
      - 'app/llm.py'
      - 'eval/goldens.jsonl'

jobs:
  eval:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run eval pipeline
        env:
          OPENROUTER_API_KEY: ${{ secrets.OPENROUTER_API_KEY }}
        run: python scripts/eval_pipeline.py
        # 退出码 0 = 通过门禁，1 = 回归，阻止合并

持续进化路线

短期（每周）

  • 每周跑一次 eval_pipeline.py，检查质量是否稳定
  • 每周添加 2-3 条新真实文章到评测集（用 add_golden.py）
  • 发现低分用例时，针对性优化 Prompt 中的对应指令

中期（每月）

  • 评测集扩充到 30+ 条，覆盖更多场景（POS、数字货币、SaaS 计费、嵌入式金融等）
  • 尝试新模型（如 GPT-4o、Claude），用同一评测集对比选型
  • 接入 CI/CD 门禁，Prompt 变更必须通过评测

长期（每季度）

  • 评测集达到 50+ 条，形成行业级黄金标准
  • 引入多维度评测（新增"相关性"、"时效性"指标）
  • 建立人工标注反馈循环：业务专家审核摘要质量，标注优秀和差劣案例
  • 实现自动 Prompt 优化：系统自动分析低分案例，生成 Prompt 改进建议
