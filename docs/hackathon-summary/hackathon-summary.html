Section · 01

项目背景

为什么选择泰国收单市场？业务聚焦点是什么？

先讲项目背景——为什么做这个项目，聚焦什么业务。

Focus · 业务聚焦

泰国收单市场的两类商机

🏦

收单 SaaS

国际收单服务商以 SaaS 模式为泰国商户提供收单服务

  • Adyen / Opn(Omise) / 2C2P / Worldpay
  • 监控重点：获牌、收购、产品发布
  • 商机等级：微弱信号（2-4 分）
🏗️

收单独立部署

泰国银行或收单机构自建或采购收单系统

  • SCB / KTB / BBL / KBank
  • 监控重点：招标、系统更换、合约到期
  • 商机等级：直接项目（8-10 分）

所有打分维度、金标准、评测指标均围绕此聚焦点设计

项目背景业务定位
项目聚焦两类业务：收单 SaaS 是国际厂商以 SaaS 模式在泰国做收单，商机偏弱，因为系统集成多由厂商自己完成；收单独立部署是泰国银行自建或采购收单系统，这是直接的项目机会，商机强度最高。所有打分、金标准、评测都围绕这两个聚焦点设计。

系统架构全链路
这是全链路架构。每天早上 8 点 GitHub Actions 自动触发：20 组 Google News 查询采集新闻，claude-opus-5 做中文摘要，gpt-5.6-sol 独立做三维打分，写入飞书多维表格，权重分 6 分以上的推送到飞书群，用户也可以通过对话机器人按需查询。整个管道免运维，密钥在 repo secrets 里。

Decisions · 技术决策

三个关键架构决策

🔀

摘要与打分模型分离

摘要用 claude-opus-5（中文质量高），打分用 gpt-5.6-sol（数学推理强）。两模型独立调用，避免一个模型既做生成又做评分的波动问题。

📜

Prompt 单一真相

打分 Prompt 存在 eval/prompts/scoring.txt，生产代码运行时读取，CI 门禁对其变更做金标准回归。改一处，生产+评测同步生效。

🗂️

单一多维表格

所有情报写入一张飞书多维表格（ADR-0001），按原文链接去重。推送状态自动流转，避免多数据源同步问题。

系统架构技术决策
三个关键决策：第一，摘要和打分用不同模型，解决 LLM-as-Judge 评分波动问题；第二，Prompt 存在单一文件里，生产和评测共用，改一处全生效，CI 会对变更做回归测试；第三，所有数据写入一张多维表格，按链接去重，避免多数据源同步。

评测体系5 维指标
打分评测用 5 个数学指标，不用 LLM-as-Judge。因为打分本身就是数值，可以直接用 MAE 和准确率衡量。右侧是当前结果——5 项全部达标。商机强度 MAE 从最初的 1.07 优化到 0.85，是迭代的主要成果。

Iteration · 三轮迭代

从 1.07 到 0.85，商机强度 MAE 的优化历程

第一轮

商机 MAE 1.07 超标。原因：金标准与 Prompt 定义不同步，SaaS 获牌/政策新闻被标为高分

第二轮

校准 40 条金标准对齐 Prompt 定义，商机 MAE 升至 1.35。原因：模型无法区分已完成项目

第三轮

Prompt 增加项目状态修正 + 政策阶段区分，商机 MAE 降至 0.85，全部达标

评测体系三轮迭代
三轮迭代过程：第一轮发现金标准和 Prompt 定义不同步，商机 MAE 超标；第二轮校准金标准后发现模型对已完成项目系统性高估，MAE 反而升高；第三轮在 Prompt 里加入项目状态修正和政策阶段区分，MAE 降到 0.85，全部达标。关键经验：金标准和 Prompt 定义必须同步。

工程化实践CI/CD 门禁
CI/CD 门禁是质量保障的核心。当有人提交 PR 修改打分 Prompt 或金标准时，GitHub Actions 自动跑 40 条金标准评测，5 个维度全部达标才允许合并，任一超标就阻断。这保证了 Prompt 变更不会引入回归。数据飞轮是更大的框架：采集、评测、对比、优化四阶段闭环，一键运行。

Optimization · 采集优化

查询词从 11 组到 20 组，噪音过滤历程

📉 优化前

  • 11 组查询词，OR 分支无 Thailand 限定
  • 时间窗口 2 天，周末几乎无新闻
  • 每渠道上限 10 条，宽查询占满名额
  • 40 条新增里大量国际噪音（加密货币、英国银行促销）
  • 飞书推送 0 条 — 高质量情报被噪音淹没
→

📈 优化后

  • 20 组查询，全部 Thailand AND (...) 强制限定
  • 时间窗口扩大到 7 天，覆盖工作日新闻
  • 每渠道上限降到 5 条，20 组分布更均匀
  • 69 条采集 / 38 条新增，泰国相关内容占比大幅提升
  • 待解决：周末高质量情报仍稀缺，考虑兜底逻辑
成果与规划采集优化
采集优化经历了从 11 组到 20 组的历程。核心问题是查询词没有 Thailand 限定，导致大量国际噪音。优化后全部用 Thailand AND 结构，时间窗口从 2 天扩到 7 天，每渠道上限从 10 降到 5。结果采集量 69 条，新增 38 条，泰国相关内容占比大幅提升。但周末高质量情报仍稀缺，正在考虑兜底逻辑。
