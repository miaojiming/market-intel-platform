三个 GitHub Actions 工作流

1. 评测门禁 eval-gate.yml

触发时机：Pull Request 修改了 Prompt、LLM 代码、评测集时自动触发

核心逻辑：运行 eval_pipeline.py → 退出码 0 通过门禁 → 退出码 1 阻止合并

# .github/workflows/eval-gate.yml
name: AI Eval Gate
on:
  pull_request:
    paths:
      - 'eval/prompts/**'
      - 'app/llm.py'
      - 'eval/goldens.jsonl'
      - 'scripts/eval_pipeline.py'

jobs:
  eval:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Set up Python
        uses: actions/setup-python@v5
        with: { python-version: '3.11' }
      - name: Install deps
        run: pip install requests feedparser beautifulsoup4 APScheduler
      - name: Run eval pipeline
        env:
          OPENROUTER_API_KEY: ${{ secrets.OPENROUTER_API_KEY }}
        run: python scripts/eval_pipeline.py
        # exit 0 = 通过, exit 1 = 回归, 阻止合并

实际效果：开发者在 PR 里改了 Prompt → GitHub Actions 自动跑 13 条评测 → 如果得分低于基线 0.05 以上，PR 无法合并，并显示哪条用例回归了。

2. 每日情报采集 daily-intelligence.yml

触发时机：每天北京时间 8:00 自动运行

核心逻辑：RSS 采集 → LLM 摘要 → 筛选高价值(importance≥4) → 飞书推送

# .github/workflows/daily-intelligence.yml
name: Daily Intelligence Report
on:
  schedule:
    - cron: '0 0 * * *'  # UTC 0:00 = 北京时间 8:00
  workflow_dispatch:      # 手动触发

jobs:
  collect:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Set up Python
        uses: actions/setup-python@v5
        with: { python-version: '3.11' }
      - name: Install deps
        run: pip install requests feedparser beautifulsoup4 APScheduler
      - name: Run intelligence collection
        env:
          OPENROUTER_API_KEY: ${{ secrets.OPENROUTER_API_KEY }}
          FEISHU_WEBHOOK_URL: ${{ secrets.FEISHU_WEBHOOK_URL }}
        run: |
          # 采集 → 摘要 → 筛选 → 推送飞书
          python -c "..."

实际效果：每天早上 8 点，系统自动从 Finextra、The Paypers 等源采集最新文章 → GLM 生成中文摘要 → 筛选出高价值情报（费率变动、系统招标等）→ 推送到飞书群。

3. 健康检查 monitor.yml

触发时机：每 6 小时自动运行

核心逻辑：检查 LLM API 连通性 + 基线状态 + 最近评测趋势 → 异常时告警

# .github/workflows/monitor.yml
name: Health Check & Monitoring
on:
  schedule:
    - cron: '0 */6 * * *'  # 每6小时
  workflow_dispatch:

jobs:

      - uses: actions/checkout@v4
      - name: Set up Python
        uses: actions/setup-python@v5
        with: { python-version: '3.11' }
      - name: Run health check
        env:
          OPENROUTER_API_KEY: ${{ secrets.OPENROUTER_API_KEY }}
        run: |
          # 1. LLM API 连通性
          # 2. 基线得分
          # 3. 最近5次评测趋势
          # 4. 异常告警 (exit 1)

配置步骤（5 步上线）

  • 创建 .github/workflows/ 目录
  • 添加三个工作流文件（eval-gate.yml、daily-intelligence.yml、monitor.yml）
  • 在 GitHub 仓库 Settings → Secrets → Actions 中添加：
    • OPENROUTER_API_KEY = 你的 OpenRouter API Key
    • FEISHU_WEBHOOK_URL = 飞书群机器人 Webhook 地址
  • 提交代码到 GitHub 仓库
  • 在 Actions 页面手动触发一次 eval-gate 验证流程

注意：GitHub Actions 的 cron 调度有 5-15 分钟延迟，且免费账户每月有限额（2000 分钟）。如果需要更精确的定时，可以考虑：

  • 使用 GitHub Actions（免费额度内够用，每日运行约 3 分钟/次）
  • 或部署到云服务器（AWS Lambda / 阿里云函数计算，按调用计费）
  • 或使用本地 Linux 服务器 + crontab（零成本）

开发者日常工作流

改 Prompt 的标准流程：

# 1. 修改 Prompt
vim eval/prompts/summarize.txt

# 2. 本地跑一次评测验证
python scripts/eval_pipeline.py

# 3. 确认无回归后提交
git add -A
git commit -m "优化Prompt：加强真实性约束"
git push

# 4. 创建 PR → GitHub Actions 自动跑评测门禁
# 5. 门禁通过（exit 0）→ 合并 → 自动更新基线
# 6. 门禁失败（exit 1）→ 查看哪条用例回归 → 修复 → 重新提交
